# GoBuddy 系统能力技术验证方案

## 1. 目标

本文档定义 GoBuddy 在正式开发前必须完成的 Windows 系统能力 PoC 和验收标准。

GoBuddy 的风险不主要在普通业务 UI，而在透明窗口、鼠标穿透、多显示器 DPI、剪贴板、全局快捷键、截图 overlay、托盘常驻和资源释放。这些能力必须先验证，再进入完整 MVP 开发。

## 2. 验证原则

- 先验证系统边界，再做完整体验。
- 每个 PoC 都必须可独立运行、可复现、可截图或记录日志。
- 失败要记录 Windows 版本、显示器、DPI、权限、异常日志。
- 任何会常驻后台的能力都要验证退出释放。
- PoC 代码后续可以迁移到 Infrastructure 层，但不能污染 Core 层。

## 5. POC-01 透明无边框置顶窗口

目标：

- 创建透明背景宠物窗口。
- 无系统边框。
- 支持置顶/取消置顶。
- 不显示任务栏按钮或可配置显示。

实现建议：

- WPF Window：
  - `AllowsTransparency=true`
  - `WindowStyle=None`
  - `Background=Transparent`
  - `Topmost=true`
  - `ShowInTaskbar=false`

验收：

- 桌宠 PNG 透明区域不显示底色。
- 切换其他应用时宠物仍可置顶。
- 关闭置顶后宠物可被其他窗口覆盖。
- 运行 10 分钟无闪烁、无明显 CPU 飙升。

## 6. POC-02 鼠标命中与穿透

目标：

- 宠物实体区域响应鼠标。
- 透明区域尽量不阻挡下层窗口。

实现路径：

| 路径 | 说明 |
| --- | --- |
| MVP 简化 | 使用粗略矩形命中，透明空白区域尽量小 |
| 推荐 | 基于 alpha mask 判断命中区域 |
| 高级 | Win32 region 或 layered window hit-test |

验收：

- 点击宠物实体触发点击动作。
- 点击宠物透明空白区域时，下层窗口可以被操作。
- 工具环和气泡仍能接收点击。
- 鼠标快速移动不会导致状态卡死。

风险：

- WPF 透明窗口默认仍可能拦截鼠标。
- Per-pixel hit-test 实现复杂，需要性能评估。

## 7. POC-03 拖拽、贴边、多屏位置

目标：

- 宠物可拖拽。
- 松手保存位置。
- 可跨显示器移动。
- 接近边缘可吸附。

验收：

- 拖拽过程中窗口跟手。
- 松手后重启应用仍在原位置。
- 副屏左侧负坐标场景下位置不丢失。
- 显示器断开后宠物能回到可见区域。

数据记录：

```json
{
  "monitorId": "DISPLAY1",
  "x": 1120,
  "y": 690,
  "scaleFactor": 1.25
}
```

## 8. POC-04 高 DPI 适配

目标：

- 宠物尺寸和截图坐标在不同 DPI 下正确。
- 多屏不同 DPI 下坐标转换不偏移。

验收：

- 100%、125%、150% DPI 下宠物视觉尺寸符合设置。
- 截图区域尺寸与用户选区一致。
- 从高 DPI 屏拖到低 DPI 屏，位置不跳变。
- 应用声明 Per Monitor DPI Awareness。

建议：

- 尽早启用 PerMonitorV2 DPI awareness。
- 坐标模型区分 DIP 和 physical pixel。

## 9. POC-05 剪贴板监听

目标：

- 监听系统剪贴板变化。
- 捕获文本、图片、文件路径。
- 避免重复保存。
- 支持暂停监听。

实现建议：

- 隐藏消息窗口。
- `AddClipboardFormatListener`。
- 处理 `WM_CLIPBOARDUPDATE`。

验收：

- 复制文本后 500ms 内生成事件。
- 复制图片后保存图片文件和元数据。
- 复制文件后记录路径列表。
- 暂停监听后不入库。
- 恢复监听后继续生效。

风险：

- 某些应用占用剪贴板导致读取失败。
- 需要重试和降级。

## 10. POC-06 剪贴板恢复

目标：

- 从历史项恢复到系统剪贴板。
- 避免恢复动作再次写入历史造成循环。

验收：

- 恢复文本后可粘贴到记事本。
- 恢复图片后可粘贴到聊天或文档。
- 恢复文件路径后可粘贴路径。
- 不产生重复历史项。

关键机制：

```text
restore item
  -> set suppression hash
  -> write clipboard
  -> ignore matching clipboard update
  -> clear suppression token
```

## 11. POC-07 全局快捷键

目标：

- 注册默认快捷键。
- 支持冲突检测。
- 退出释放。

默认快捷键：

| 动作 | 快捷键 |
| --- | --- |
| 打开剪贴板 | Alt + V |
| 区域截图 | Alt + Shift + S |
| 显示/隐藏宠物 | Alt + Shift + P |
| 打开 AI 面板 | Alt + Shift + A |

验收：

- 快捷键触发对应应用事件。
- 快捷键冲突时 UI 可提示失败。
- 退出应用后快捷键释放。
- 连续触发不会创建多个重复窗口。

## 12. POC-08 系统托盘

目标：

- 应用可常驻托盘。
- 托盘菜单可操作核心功能。
- 退出时释放托盘图标。

菜单：

- 显示/隐藏宠物。
- 打开剪贴板。
- 开始截图。
- 暂停监听。
- 设置。
- 退出。

验收：

- 关闭主窗口不退出应用。
- 托盘菜单可正常触发。
- 退出后托盘图标不残留。

## 13. POC-09 区域截图 overlay

目标：

- 进入截图模式后显示覆盖层。
- 鼠标框选区域。
- 输出截图。
- 写入剪贴板。

验收：

- Esc 可取消。
- 单屏截图尺寸正确。
- 双屏截图区域正确。
- 负坐标显示器截图正确。
- 截图后可粘贴到常见应用。
- overlay 不残留、不吞掉焦点。

坐标记录：

```json
{
  "monitorId": "DISPLAY2",
  "x": -640,
  "y": 180,
  "width": 512,
  "height": 338,
  "scaleFactor": 1.5
}
```

## 14. POC-10 SQLite 与文件存储

目标：

- 初始化 `%AppData%\GoBuddy`。
- 初始化 SQLite。
- 保存文本、图片、截图元数据。
- 清理过期数据和孤儿文件。

验收：

- 首次启动自动创建数据库。
- 应用重启后历史仍可查询。
- 图片文件存在且路径有效。
- 清空历史时文件同步删除。
- 数据库损坏时能提示并备份坏库。

## 15. POC-11 开机启动

目标：

- 设置页可开启/关闭开机启动。

实现候选：

| 方式 | 说明 |
| --- | --- |
| Startup 文件夹快捷方式 | 简单，适合 MVP |
| 注册表 Run | 常见，但要注意权限 |
| MSIX StartupTask | 若采用 MSIX，可用系统能力 |

验收：

- 开启后重启系统应用可启动。
- 关闭后不再启动。
- 安装路径变化时不会留下坏项。

## 16. POC-12 AI/CLI Provider 探测

目标：

- 检测 Codex CLI、Claude Code CLI、自定义命令是否可用。
- 不执行有副作用命令。

允许命令：

- `codex --version`
- `claude --version`
- 自定义命令仅允许 `--version` 或用户显式配置的只读探测命令。

验收：

- 未安装时显示 `not_installed`。
- 已安装时显示版本和路径。
- 探测超时可取消。
- 探测日志不记录敏感环境变量。

## 18. 阶段 0 通过标准

进入 MVP 正式开发前，必须满足：

- POC-01 到 POC-10 全部通过。
- POC-11 可以延后到设置页阶段，但需明确实现路径。
- POC-12 可以先 mock，但探测安全策略必须确定。
- 所有 failed 项必须有明确修复方案或产品降级策略。

## 19. 建议执行顺序

1. 透明窗口。
2. 鼠标命中/穿透。
3. 拖拽和多屏位置。
4. DPI。
5. 托盘。
6. 快捷键。
7. 剪贴板监听。
8. 剪贴板恢复。
9. 截图 overlay。
10. SQLite 与文件存储。
11. 开机启动。
12. AI/CLI Provider 探测。

## 20. 输出物

阶段 0 完成后应产出：

- `poc-report.md`
- 每个 PoC 的最小代码或迁移到正式 Infrastructure 的实现。
- 关键截图。
- 已知问题列表。
- MVP 是否可继续推进的技术结论。
