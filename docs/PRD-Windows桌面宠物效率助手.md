## 2. 产品一句话

GoBuddy 是一个常驻桌面的互动宠物效率助手，它既能陪伴用户、响应鼠标互动，也能作为剪贴板历史、截图和临时信息管理的轻量入口。

## 3. 背景与机会

Windows 用户已经有系统级剪贴板历史、截图工具、第三方截图软件和剪贴板管理器，但这些工具通常是分散的、工具感强的、缺少陪伴感的。

桌面宠物类产品有陪伴感和视觉记忆点，但多数停留在装饰、动画和简单互动层面，缺少真实生产力价值。

GoBuddy 的机会在于把两类需求结合起来：

- 桌面宠物提供持续存在感和情绪连接。
- 剪贴板、截图、快速收纳提供真实使用频率。
- 宠物行为与效率工具联动，形成区别于传统工具软件的产品识别度。

## 4. 产品目标

### 4.1 MVP 目标

- 实现一个可长期常驻桌面的互动宠物。
- 支持基础鼠标互动：靠近、点击、拖拽、悬停、释放。
- 提供可用的剪贴板历史管理能力。
- 提供基础区域截图能力。
- 通过全局快捷键和托盘菜单完成主要功能调用。
- 所有核心数据默认本地存储，保护隐私。

### 4.2 非目标

MVP 阶段暂不追求：

- 完整 AI 助手能力。
- 云同步、多设备同步。
- 复杂截图编辑器。
- 插件市场。
- 多宠物生态。
- 社交、养成、付费皮肤商城。
- 跨平台支持。

## 5. 目标用户

### 5.1 核心用户

1. 学生和知识工作者
   - 高频复制网页、论文、笔记、图片。
   - 需要找回之前复制过的内容。
   - 经常截图并插入到文档或聊天中。

2. 开发者、设计师、运营人员
   - 高频复制代码片段、链接、颜色值、错误信息。
   - 经常截图反馈问题、记录界面、标注信息。
   - 喜欢快捷键和常驻小工具。

3. 桌面美化和陪伴型用户
   - 愿意让一个可爱的角色常驻桌面。
   - 对互动反馈、情绪状态、可定制形象有兴趣。

### 5.2 用户痛点

- 复制内容容易被新内容覆盖。
- 系统剪贴板历史入口弱，组织和搜索能力有限。
- 截图工具与剪贴板工具割裂。
- 传统效率工具缺少趣味和情绪反馈。
- 桌宠产品好玩但缺少刚需功能，留存弱。

## 6. 产品定位

GoBuddy 不是单纯桌宠，也不是披着皮肤的工具箱，而是一个“桌面伙伴型效率工具”。

产品核心身份：

- 陪伴者：有动画、有状态、有回应。
- 收纳员：帮用户保存复制过的文本、图片和文件路径。
- 小工具员：帮用户快速截图、找回内容和触发常用动作。

## 7. 核心使用场景

### 7.1 复制资料后找回

用户连续复制多段文本、链接或图片。稍后发现需要使用之前复制过的内容，按下快捷键打开剪贴板面板，搜索或选择历史项，一键重新复制或直接粘贴。

### 7.2 快速区域截图

用户点击宠物或使用快捷键进入截图模式，框选屏幕区域。截图自动进入剪贴板，也保存到历史记录中，便于之后再次使用。

### 7.3 鼠标互动陪伴

用户鼠标靠近宠物时，宠物看向鼠标；点击时做出反应；拖拽时被提起；释放时落地或弹跳；闲置时进入待机、睡觉或走动状态。

### 7.4 宠物联动效率动作

当用户复制内容时，宠物出现轻微“收纳”动作；截图完成后，宠物短暂展示成功反馈；剪贴板历史有收藏项时，宠物可提示“已收藏”状态。

## 9. 功能需求

## 9.1 桌宠窗口

### 需求描述

桌宠以透明无边框窗口常驻桌面，可显示在其他窗口之上，也可设置为不置顶。

### 关键需求

- 支持透明背景。
- 支持置顶显示。
- 支持鼠标拖拽移动。
- 支持右键打开快捷菜单。
- 支持贴边吸附。
- 支持大小调整。
- 支持暂停互动。
- 支持显示/隐藏。

### 验收标准

- 宠物窗口背景透明，不显示系统窗口边框。
- 拖拽宠物时移动流畅，无明显闪烁。
- 右键宠物可打开菜单。
- 宠物可以通过托盘恢复显示。
- 多显示器环境下，宠物能正确移动到不同屏幕。

## 9.2 宠物状态与动画

### MVP 状态

| 状态 | 触发条件 | 表现 |
| --- | --- | --- |
| Idle | 无用户操作 | 呼吸、眨眼、轻微待机动作 |
| LookAtCursor | 鼠标进入感应范围 | 面向或看向鼠标方向 |
| Hover | 鼠标悬停在宠物上 | 好奇、挥手或提示动作 |
| Clicked | 左键点击 | 被戳、开心或轻微弹跳 |
| Dragging | 鼠标按住拖拽 | 被提起或拉动 |
| Dropped | 拖拽释放 | 落地、弹跳或恢复站立 |
| ClipboardSaved | 检测到新剪贴板内容 | 收纳动作 |
| ScreenshotDone | 截图完成 | 成功反馈动作 |
| Sleeping | 长时间无操作 | 睡觉或低功耗动画 |

### 验收标准

- 每个 P0 状态至少有一个明确视觉反馈。
- 状态切换不会卡死或出现动画冲突。
- 快速连续点击、拖拽、释放时不崩溃。

## 9.3 鼠标交互

### 关键需求

- 鼠标靠近宠物时触发注视。
- 鼠标悬停时触发轻反馈。
- 左键点击触发宠物反应。
- 左键按住可拖拽宠物。
- 右键打开菜单。
- 双击可打开默认面板，默认建议为剪贴板历史。

### 交互边界

- 宠物实体区域响应鼠标事件。
- 透明区域应尽量不阻挡用户操作其他窗口。
- 当打开截图、剪贴板面板等工具时，宠物交互不应抢焦点。

## 9.4 托盘菜单

### 菜单项

- 显示/隐藏宠物
- 打开剪贴板历史
- 开始截图
- 暂停剪贴板监听
- 设置
- 关于
- 退出

### 验收标准

- 应用启动后托盘图标可见。
- 关闭主窗口不退出应用，除非用户选择退出。
- 退出时释放快捷键和后台监听。

## 9.5 全局快捷键

### 默认快捷键

| 功能 | 默认快捷键 |
| --- | --- |
| 打开剪贴板历史 | Alt + V |
| 开始区域截图 | Alt + Shift + S |
| 显示/隐藏宠物 | Alt + Shift + P |

### 需求

- 支持快捷键自定义。
- 快捷键冲突时提示用户。
- 快捷键注册失败时不影响应用启动。

## 9.6 剪贴板历史

### 支持类型

- 文本
- 图片
- 文件路径列表

### 核心能力

- 自动监听系统剪贴板变化。
- 新内容写入历史记录。
- 重复内容去重。
- 支持搜索文本内容。
- 支持收藏。
- 支持删除单条记录。
- 支持清空历史。
- 支持按类型筛选。
- 支持限制历史保留天数和最大条数。

### 数据字段

| 字段 | 说明 |
| --- | --- |
| id | 唯一 ID |
| type | text / image / file |
| content_text | 文本内容或文件路径摘要 |
| content_blob_path | 图片等二进制内容路径 |
| preview | 预览内容 |
| hash | 内容哈希，用于去重 |
| is_favorite | 是否收藏 |
| created_at | 创建时间 |
| last_used_at | 最近使用时间 |
| source_app | 来源应用，可选 |

### 隐私需求

- 支持暂停监听。
- 支持排除特定应用。
- 支持敏感内容规则过滤。
- 默认不上传剪贴板内容。
- 密码类内容应尽量不入库。

### 敏感内容过滤初版规则

- 长度较短且来自密码管理器进程时不保存。
- 命中常见密钥格式时不保存，例如 API Key、Token、私钥头。
- 用户可手动添加正则过滤规则。

## 9.7 剪贴板历史面板

### 面板能力

- 通过快捷键、托盘或宠物双击打开。
- 支持搜索。
- 支持按类型筛选。
- 支持复制选中项。
- 支持删除、收藏。
- 支持键盘上下选择。
- 支持 Enter 复制或粘贴。
- 支持 Esc 关闭。

### 推荐布局

- 顶部：搜索框与类型筛选。
- 中部：历史列表。
- 右侧或展开区：内容预览。
- 底部：快捷操作提示和设置入口。

### 验收标准

- 1000 条文本历史下搜索和滚动保持流畅。
- 图片历史有缩略图。
- 文件路径历史显示文件名和路径。
- 从面板选择历史项后，系统剪贴板被正确更新。

## 9.8 截图功能

### MVP 截图能力

- 区域截图。
- 截图后复制到剪贴板。
- 截图后保存到剪贴板历史。
- 截图过程中显示半透明遮罩。
- 支持 Esc 取消截图。

### P1 标注能力

- 矩形
- 箭头
- 画笔
- 文字
- 马赛克
- 撤销
- 保存到文件

### 验收标准

- 多显示器下可以截取正确屏幕区域。
- 截图尺寸与用户选择区域一致。
- 截图后可以直接粘贴到微信、浏览器、文档等常见应用。
- 取消截图不会写入历史。

## 9.9 设置页

### 设置项

- 开机自启动。
- 宠物显示大小。
- 是否置顶。
- 是否贴边吸附。
- 剪贴板历史保留天数。
- 剪贴板最大记录数。
- 是否保存图片历史。
- 快捷键设置。
- 隐私过滤规则。
- 排除应用列表。
- 数据清理。

## 9.10 关于页

### 内容

- 应用名称和版本。
- 本地数据说明。
- 开源依赖说明。
- 反馈入口。

## 10. 关键交互流程

### 10.1 启动流程

1. 用户启动应用。
2. 应用注册托盘图标和全局快捷键。
3. 加载用户设置。
4. 加载宠物窗口。
5. 启动剪贴板监听。
6. 宠物进入 Idle 状态。

### 10.2 复制内容流程

1. 用户在任意应用复制内容。
2. GoBuddy 监听到剪贴板变化。
3. 判断内容类型。
4. 执行去重和敏感内容过滤。
5. 写入本地历史。
6. 宠物播放 ClipboardSaved 动画。

### 10.3 使用剪贴板历史流程

1. 用户按 Alt + V。
2. 打开剪贴板历史面板。
3. 用户搜索或选择历史项。
4. 用户按 Enter 或点击复制。
5. 系统剪贴板更新为该历史项。
6. 面板关闭或保持，依据用户设置。

### 10.4 截图流程

1. 用户按 Alt + Shift + S 或从宠物菜单选择截图。
2. 应用进入截图模式。
3. 屏幕显示遮罩。
4. 用户拖拽选择区域。
5. 应用生成截图。
6. 截图写入系统剪贴板。
7. 截图保存到历史。
8. 宠物播放 ScreenshotDone 动画。

## 11. 技术方案建议

### 11.1 推荐技术栈

| 模块 | 推荐方案 |
| --- | --- |
| 桌面框架 | .NET 8 + WPF |
| UI | WPF / XAML |
| 本地数据库 | SQLite |
| 图片存储 | 本地文件 + SQLite 元数据 |
| 全局快捷键 | Win32 RegisterHotKey |
| 剪贴板监听 | Windows Clipboard API |
| 截图 | Win32 / WPF 屏幕捕获 |
| 托盘 | NotifyIcon |
| 安装包 | Inno Setup 或 MSIX |

### 11.2 为什么优先 WPF

- Windows 透明窗口和无边框窗口能力成熟。
- 鼠标事件、置顶、托盘、快捷键和 Win32 互操作资料充分。
- 相比跨平台框架，在 Windows 桌宠场景下更少处理系统边界问题。
- 后续可以逐步接入更复杂的动画资源。

### 11.3 可参考的成熟项目

- ShareX：Windows 截图、录屏、上传和生产力工具，适合参考截图能力和工作流设计。
- CopyQ：成熟剪贴板管理器，适合参考历史、搜索、收藏、标签等能力。
- PasteBar：现代剪贴板管理器，适合参考跨平台剪贴板体验。
- Flameshot：适合参考区域截图和标注工具栏交互。

注意：参考成熟项目时必须检查开源协议。MVP 阶段建议先参考产品交互和架构思路，避免直接复制 GPL 项目代码导致后续商业化受限。

## 13. 隐私与安全

### 13.1 原则

- 默认本地优先。
- 默认不上传用户剪贴板和截图。
- 用户可以随时清空历史。
- 用户可以暂停监听。
- 对敏感内容采取默认保护。

### 13.2 风险点

- 剪贴板可能包含密码、Token、身份证号等敏感信息。
- 截图可能包含私人画面。
- 开机自启动和常驻后台可能引发用户不信任。

### 13.3 产品处理

- 首次启动时说明本地存储策略。
- 设置页提供“暂停监听”和“清空所有数据”。
- 对疑似密钥和密码管理器来源内容默认不保存。
- 后续如加入云同步，必须单独开启并明确告知。

## 14. 性能要求

- 应用冷启动目标：3 秒内显示宠物。
- 常驻内存目标：MVP 尽量低于 200 MB。
- 宠物动画空闲 CPU 占用：尽量低于 3%。
- 剪贴板面板打开：300ms 内响应。
- 1000 条历史内搜索：500ms 内返回结果。
- 截图模式进入：500ms 内显示遮罩。

## 15. 兼容性要求

- 支持 Windows 10 及以上。
- 支持 Windows 11。
- 支持高 DPI 缩放。
- 支持多显示器。
- 支持明暗主题。
- 支持中文界面，后续可扩展英文。

## 16. 可访问性要求

- 核心工具功能必须可通过键盘完成。
- 剪贴板面板支持上下选择、Enter、Esc。
- 设置项文本明确。
- 不依赖颜色作为唯一状态提示。

## 17. 开发里程碑

### 阶段 0：技术验证

目标：验证 Windows 桌宠核心可行性。

- 托盘常驻。
- 全局快捷键。
- 剪贴板监听。
- 区域截图原型。

目标：完成可用闭环。

- 桌宠基础动画和状态机。
- 剪贴板历史记录。

- 区域截图。

目标：提升产品质感。

## 19. 关键产品决策

### 19.1 第一版宠物形象

建议第一版采用低成本、可控的 2D 序列帧或 GIF 风格，不在 MVP 阶段引入复杂 Live2D。

理由：

- 降低动画管线复杂度。
- 更容易快速实现状态反馈。
- 方便后续替换资源。

### 19.2 第一版截图能力

建议第一版只做区域截图和复制到剪贴板，标注功能放到 P1。

理由：

- 截图的基础闭环更重要。
- 标注编辑器复杂度较高，容易拖慢 MVP。

### 19.3 第一版剪贴板能力

建议第一版重点做好文本和图片历史。

理由：

- 高频场景明确。
- 文件路径支持可以做，但不需要一开始做复杂文件管理。

### 19.4 第一版 AI 能力

建议 MVP 不内置 AI。

理由：

- AI 会引入账号、成本、隐私、网络和期望管理问题。
- 先验证桌宠效率助手这个核心形态。

### 19.5 未来 AI 与本地 CLI 能力预留

虽然 MVP 不实现真实 AI 后端，但产品设计和前端信息架构需要为后续 AI 能力预留入口。

#### 目标定位

GoBuddy 未来的 AI 能力不应只做普通聊天窗口，而应成为桌宠效率场景的延伸：

- 解释当前剪贴板内容。
- 总结截图或 OCR 结果。
- 根据复制的错误信息生成排查步骤。
- 将用户意图转成可交给本地 Agent CLI 执行的任务。
- 通过桌宠反馈展示任务状态、风险提醒和完成结果。

#### 本地 CLI 集成方向

未来优先考虑接入用户本机已安装的开发者工具，而不是一开始自建云端 Agent。

| 集成对象 | 未来用途 | MVP 处理 |
| --- | --- | --- |
| Codex CLI | 本地代码修改、任务拆解、项目上下文问答 | 前端展示入口和连接状态，不执行命令 |
| Claude Code CLI | 代码审阅、重构建议、长上下文问答 | 前端展示入口和连接状态，不执行命令 |
| 自定义本地命令 | 接入其他 Agent、MCP 服务或企业内部命令 | 设置页预留配置入口 |

#### 产品原则

- 本地优先：默认优先调用用户本机 CLI 和本地工作区。
- 明确授权：执行命令前必须让用户确认命令、目录和权限。
- 可审计：保留任务请求、命令摘要、执行状态和结果摘要。
- 不静默执行：任何会修改文件、访问网络或读取敏感目录的动作都需要显式确认。
- 可降级：未安装 CLI 时，AI 面板仍可作为功能说明和配置入口。

#### 前端预留范围

MVP 原型中可以预留：

- AI 工具入口。
- 本地 CLI Provider 选择。
- 连接状态：未安装、待连接、已连接、执行中、失败。
- Prompt 输入区。
- 快捷动作：总结剪贴板、解释截图、生成 CLI 任务。
- 任务状态反馈：等待确认、执行中、完成、失败。

MVP 不实现：

- 真实 CLI 调用。
- 真实模型请求。
- 文件系统读取。
- 命令执行。
- 账号、Token 或云端同步。

## 20. 风险与应对

| 风险 | 影响 | 应对 |
| --- | --- | --- |
| 透明窗口阻挡用户操作 | 用户反感 | 精确命中宠物区域，透明区域尽量鼠标穿透 |
| 剪贴板保存敏感内容 | 隐私风险 | 默认过滤、暂停监听、排除应用、清空数据 |
| 桌宠消耗性能 | 常驻体验差 | 限制动画帧率，睡眠状态降低刷新 |
| 功能过多导致 MVP 失焦 | 开发周期拉长 | 严格 P0/P1/P2 分层 |
| 截图多屏/DPI 问题 | 核心功能不稳定 | 阶段 0 专门验证多屏和高 DPI |
| 开源协议污染 | 后续商业化受限 | 只参考交互与架构，谨慎复用 GPL 代码 |
